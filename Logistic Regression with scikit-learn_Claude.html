Module 1 · Basics

A yes/no question, answered with a probability

Will this customer leave? Will this loan default? Is this email spam? Logistic regression answers questions like these with a number between 0 and 1.

What

Logistic regression is a classification model. The name says "regression" because it borrows the first half of linear regression, but its job is to predict which of two groups a case belongs to.

It works in two steps. First it adds up the evidence: each feature is multiplied by a weight, and the results are summed into one score called z. Then it squashes that score into a probability with the sigmoid function.

z = b0 + b1·x1 + b2·x2 + …    then    P(yes) = 1 / (1 + e−z)

A large positive z gives a probability near 1, a large negative z gives a probability near 0, and z = 0 gives exactly 0.5.

Why

You could fit an ordinary straight line to a 0/1 outcome. The figure shows what happens when you do that with our churn data: the line keeps falling, and for long-tenured customers it predicts a churn probability below zero.

Three more reasons it is usually the first classifier people reach for: it trains in milliseconds, its weights can be read and explained to a manager, and it outputs probabilities you can rank and budget against.

How

Before any code, get a feel for the curve. The model with one feature has two numbers: a weight and an intercept. Move them and watch what each one does.

Training a logistic regression means finding the weights that make this curve fit your data best. From module 3 onward, scikit-learn does that search for you.

Module 2 · Basics

Meet the 1,000 customers

One dataset carries the whole tutorial: customers of a subscription telecom company, and whether each one cancelled.

What

Each row is one customer. Five columns describe the customer and the sixth, churn, is the answer we want to predict: 1 if they left, 0 if they stayed.

ColumnTypeMeaning
tenure_monthsnumberMonths as a customer, 1 to 72
monthly_chargesnumberMonthly bill in dollars, 20 to 120
support_callscountCalls to customer support in the last quarter
contractcategoryMonth-to-month, One year, or Two year
autopay0 / 11 if the bill is paid automatically
churn0 / 1Target. 1 if the customer cancelled
Why

The data is synthetic: the code below invents it from a fixed random seed. That has two advantages for learning. You can recreate the exact same rows without downloading a file, and because we wrote the rule that decides who churns, we can later check whether the model found it (module 5).

Churn is also a typical business use of this model. The outcome is yes/no, the company wants a ranked list of at-risk customers, and it needs to know which factors drive the risk.

How

Create the dataset. You need numpy, pandas and scikit-learn installed (pip install scikit-learn pandas); a Jupyter or Colab notebook works well.

Always look at the target before modelling. How common is a "yes"?

One customer in four churned. Keep that number in mind: a model that predicts "stays" for everyone would already be right 75% of the time, so 75% is the score to beat.

Module 3 · Basics

Your first model: one feature, one curve

Predict churn from tenure alone. The whole model is two numbers.

What

With one feature the model is P(churn) = sigmoid(b0 + b1 × tenure). Fitting the model means choosing b0 and b1 so the curve agrees with the data as closely as possible.

"As closely as possible" needs a score. Logistic regression uses log loss: for every customer, take the probability the model gave to what actually happened, and average the negative logarithms.

log loss = − average of [ y·ln(p) + (1 − y)·ln(1 − p) ]
Why

Log loss rewards honest probabilities. Suppose a customer stayed. A model that said "60% chance of churn" pays −ln(0.4) = 0.92 for that customer. A model that said "90% chance of churn" pays −ln(0.1) = 2.30. Being confidently wrong costs much more than being unsure, so the best strategy is to report probabilities that match reality.

A model that says 50% for everyone scores ln(2) = 0.693. Anything lower means the model has learned something.

How

Try the fitting job by hand first. Move the two sliders to pull the curve through the grey dots and watch the log loss fall.

Now let scikit-learn do it. Every scikit-learn model follows the same three calls: create it, fit it, then predict.

The slope is negative: longer tenure, lower churn. Ask for predictions for three new customers.

predict_proba returns one column per class. A 3-month customer has a 50.7% chance of leaving, a 60-month customer 10.7%. predict turns those into labels by asking whether P(churn) is at least 0.5.

Module 4 · Core skills

Many features, one pipeline

Use all five columns, hold back test data, and wrap the preparation steps and the model into a single object.

What

Adding features adds terms to z. The shape of the model stays the same. With two features, the set of customers at exactly 50% forms a straight line that splits the chart into a "predict churn" side and a "predict stay" side. With more features it is a flat plane in more dimensions. This is why logistic regression is called a linear classifier.

Real tables need three preparation steps before the model can use them: split the rows, scale the numbers, and encode the categories.

Why
  • Split into training and test rows because a model always looks good on data it has already seen. The test rows stand in for future customers.
  • Scale numeric columns to mean 0 and standard deviation 1. Tenure runs to 72 and autopay only to 1; without scaling, the solver works harder and regularization (module 7) treats the columns unfairly.
  • Encode contract as 0/1 columns because the model needs numbers. One-hot encoding makes one column per category; dropping the first makes Month-to-month the reference that the others are compared with.
  • Pipeline them together so the scaler learns its mean and standard deviation from training rows only. Learning them from all rows lets information about the test set leak into training.
How

Split first. stratify=y keeps the churn rate the same in both parts.

The model is right for 86.4% of test customers against a 75.2% baseline. Test accuracy coming out above training accuracy is unusual; it is the luck of this particular split, and module 8 shows how to measure that luck.

Module 5 · Core skills

Reading the coefficients

The fitted weights tell you which factors push churn up or down, and by how much.

What

Coefficients live on the log-odds scale, so you need three ways of saying the same thing:

ProbabilityOdds = p / (1 − p)Log-odds = ln(odds)
0.200.25  (1 to 4)−1.39
0.501.00  (even)0.00
0.804.00  (4 to 1)+1.39

A coefficient is the change in log-odds when its feature goes up by one unit and the others stay fixed. Take e to the power of the coefficient and you get the odds ratio: the number the odds are multiplied by. Above 1 raises the odds, below 1 lowers them.

Why

This is the main reason analysts still choose logistic regression when fancier models exist. A retention team can act on "each extra support call multiplies the odds of churn by about 1.8". It cannot act on a black-box score.

Coefficients describe association in this data. They say customers on two-year contracts churn less; they do not prove that moving a customer to a two-year contract will make that customer stay.

How

Pull the coefficients out of the pipeline and convert them to odds ratios with np.exp.

Read two of them. A two-year contract has an odds ratio of 0.086: the odds of churn are about 91% lower than for a month-to-month customer who is otherwise the same. Autopay has 0.677: odds about 32% lower.

The numeric columns were scaled, so their coefficients are per standard deviation. Divide by the scaler's standard deviations to get them per month, per dollar and per call. Since we invented the data, we can put the hidden rule from module 2 beside them:

The model recovered the rule closely from 750 training rows. It is not exact, because the sample is finite and because scikit-learn applies a little regularization by default (module 7).

An odds ratio is not a change in probability. Turning autopay on always multiplies the odds by 0.677, but the probability drop depends on where the customer started. Try it in the calculator with a risky customer and then a safe one.

Module 6 · Core skills

Evaluating predictions

A probability becomes a decision only when you choose a cut-off. That choice decides which mistakes you make.

What

predict labels a customer "churn" when P(churn) is at least 0.5. Every labelled customer then falls into one of four boxes, laid out in a confusion matrix: caught churners, missed churners, false alarms, and correctly ignored customers.

  • Accuracy: share of all customers labelled correctly.
  • Precision: of those flagged as churners, the share who really churned.
  • Recall: of those who really churned, the share you flagged.
  • F1: one number that balances precision and recall.
  • ROC AUC: the chance the model ranks a random churner above a random stayer. It does not depend on any threshold; 0.5 is guessing, 1.0 is perfect.
Why

Accuracy alone hides the mistakes that matter. Missing a churner loses a customer. Flagging a loyal customer costs one unneeded retention offer. Those costs are rarely equal, so the default 0.5 is rarely the best cut-off for the business.

How

At the default threshold the model catches 36 of 62 churners (recall 0.58) and raises 8 false alarms. Move the threshold below and watch the trade.

Module 7 · Advanced

Regularization: keeping coefficients in check

scikit-learn's logistic regression penalizes large weights by default. Knowing how to set that penalty is the main tuning skill for this model.

What

Regularization adds a cost for large coefficients to the log loss, so the model prefers smaller weights unless the data argues strongly for big ones.

  • C sets the strength, and it is inverted: a small C means a strong penalty. The default is C=1.0.
  • L2 (ridge, the default) shrinks all coefficients smoothly toward zero.
  • L1 (lasso) pushes the weakest coefficients to exactly zero, which removes those features from the model.

Because the default is not "no penalty", scikit-learn's coefficients differ slightly from those of statistics packages. Pass C=np.inf for an unpenalized fit.

Why

With many features and few rows, an unpenalized model fits noise: weights grow large to explain quirks of the training sample and predictions on new data get worse. A penalty trades a little training fit for stability. L1 has an extra use, since a model with fewer features is easier to explain and cheaper to feed.

Our dataset has six informative columns and 750 training rows, so the penalty has little to fix here. That makes it a clean place to see what C does.

How

At C = 0.001 the weights are squeezed nearly to zero and the model falls back to the 75.2% baseline. From C = 1 upward accuracy stops changing and the coefficients settle.

In code, l1_ratio=1 selects the L1 penalty, and it needs a solver that supports it:

With a strong L1 penalty only tenure and support calls survive. The model has chosen its two most useful features on its own.

Module 8 · Advanced

Validation and tuning

Measure performance in a way that does not depend on one lucky split, choose settings without touching the test set, and handle a rare "yes" class.

What
  • Cross-validation splits the training rows into k parts (folds). It trains on k − 1 of them, scores on the one left out, and repeats until every fold has been the left-out one. You get k scores instead of one.
  • Grid search runs cross-validation for every combination of settings you list and keeps the best.
  • Class weights make mistakes on the rare class count for more during training.
Why

A single test score is one draw from a noisy process. Our own model shows it: the test AUC was 0.902, yet the five cross-validation folds below range from 0.774 to 0.898. The test split happened to be an easy one.

Tuning has its own trap. If you pick C by looking at test scores, the test set has helped train the model and its score stops being an honest estimate. Tune with cross-validation on the training rows, and open the test set once at the end.

How

Now search over C and the penalty type. Pipeline step names prefix the setting: model__C means "the C of the step called model".

The search landed on the defaults, C = 1 with L2. That is a real and common result: on clean, low-dimensional data, tuning buys little. You still needed the search to know that.

When the "yes" class is rare

With class_weight="balanced", each churner counts about three times as much as a stayer in the loss, in proportion to how rare churners are.

Balanced weights have much the same effect as lowering the threshold in module 6. They also inflate the predicted probabilities, so do not read them as true churn rates. If you need honest probabilities, keep the default weights and move the threshold instead.

Module 9 · Advanced

Going further

Curved boundaries, more than two classes, and the mistakes worth checking for before you trust a model.

What
  • Non-linear terms. Add squares and products of features and the same model can draw a curved boundary.
  • Multiclass. With three or more classes, scikit-learn fits one set of weights per class and uses the softmax function so the probabilities sum to 1. You change nothing in your code.
  • Statistical inference. scikit-learn reports no p-values or confidence intervals. When you need them, fit the same model with the statsmodels library.
Why

A plain logistic regression assumes each feature moves the log-odds in a straight line and that features do not interact. When that is false, for example if support calls matter only for new customers, extra terms let the model see it. Extra terms also give the model more ways to overfit, so they have to earn their place in cross-validation.

How

The richer model scores slightly worse. That is the honest answer for this dataset: the hidden rule from module 2 is a straight line in log-odds, so squares and interactions only add noise. On real data, run this same comparison and keep whichever wins.

Before you trust a model

  • Compared with the "always predict the majority" baseline.
  • Scaling and encoding sit inside a pipeline, fitted on training rows only.
  • No feature leaks the answer, such as a "cancellation date" column.
  • Numeric features are scaled before regularization is applied.
  • You remembered the default L2 penalty when reading coefficients.
  • Odds ratios are reported as changes in odds, not in probability.
  • The threshold was chosen from costs, not left at 0.5 by habit.
  • Performance is quoted from cross-validation, with its spread.
  • A ConvergenceWarning was fixed by scaling or a larger max_iter.

At z = 0, both outcomes have estimated probability 50%.

WHAT

A classifier with a probability

Logistic regression predicts a class, such as conversion (1) or no conversion (0). Despite its name, it is used for classification.

WHY

Uncertainty matters

A customer with p = 0.80 has an estimated 80% chance of conversion under the model. This is an estimate, not a promise or a claim of 80% model accuracy.

HOW

First, calculate a score

Combine input features with learned weights. Then apply the sigmoid function.

z = b₀ + b₁x₁ + b₂x₂

Here, x₁ and x₂ are customer features. b₀ is the intercept; b₁ and b₂ are coefficients.

Try this

Compare z = −4, 0, and +4. Where does a one-unit change in z change the probability most?

Explore the idea

The curve is steepest near z = 0. Near either end, it flattens. The sigmoid maps every finite score to a probability strictly between 0 and 1.

What if the settings are fixed in advance?

If you fix all settings before inspecting results and make no changes based on those results, a training/test split is sufficient. Log loss measures probability error; lower is better. This displayed loss excludes the penalty. AUC measures ranking; higher is better.

Five models were fitted with scikit-learn in advance, using the same 180 training customers. Changing C loads a different fitted model and evaluates it on the same 60 validation customers. If you choose C using those results, you are manually tuning a model hyperparameter. Section 4 reproduces one fit at a time.

What does fitting do?

fit(X_train, y_train) finds coefficients that reduce log loss plus a regularization penalty. It uses the observed training labels.

Why scale the features?

StandardScaler subtracts each training mean and divides by its training standard deviation. This makes the penalty more comparable across features.

x_scaled = (x − mean) / std

Fit the scaler on training data only. Reuse those values for validation, test, and new customers.

Association is not causation

A positive coefficient means a higher feature value raises the estimated log-odds, holding the other feature fixed. It does not prove that causing more clicks will cause more sales.

03 · Decide, then evaluate

60 VALIDATION CUSTOMERS
The decision rule

Predict conversion when p ≥ threshold.

C = 1

The model gives a probability. You choose the rule for acting on it. Moving the threshold changes class predictions; it does not refit the model.

0.00 · predict everyone as 11.00 · predict nobody as 1 here
Predict before you moveLower the threshold from 0.75 to 0.25. Does recall go up or down? Does precision have to change in the opposite direction?
Explain the trade-off

Lowering the threshold can only add predicted positives. Recall therefore cannot decrease. False positives can also increase. Precision can rise, fall, or stay the same on a finite dataset; it is not guaranteed to move monotonically.

Precision

Of predicted conversions, how many actually converted?

Recall

Of actual conversions, how many did we find?

Accuracy

Fraction of all predictions that are correct.

F1 score

Harmonic mean of precision and recall.

2TP / (2TP + FP + FN)

A zero denominator is shown as N/A. Accuracy can hide weak detection of the minority class.

Read the workflow
  1. Make X and yX is a DataFrame with two feature columns. y is a Series of observed 0/1 outcomes.
  2. Split before learningUse training data to fit. Use validation data for choices. Reserve test data for the final check. Stratification keeps class proportions similar.
  3. Build a PipelineThe scaler and classifier stay together. Calling fit learns scaling and coefficients from training data only.
  4. Get probabilitiespredict_proba returns one row per customer and one column per class. Use classes_ to find the column for class 1.
  5. Choose a threshold(prob_val ≥ threshold).astype(int) turns probabilities into class labels.
  6. Inspect mistakesconfusion_matrix(..., labels=[0, 1]) returns [[TN, FP], [FN, TP]]. Use precision and recall to describe different mistakes.

Avoid these common errors

Do not fit a scaler on the full dataset before splitting. Do not fit a new scaler on validation or test data. Do not select settings from test results.

With cross-validation, put preprocessing inside the pipeline so it is fitted separately inside each training fold. A pipeline cannot prevent leakage from a feature that contains future information.

What if I add categorical features?

Use a ColumnTransformer: StandardScaler for numeric columns and OneHotEncoder(handle_unknown="ignore") for categories. Place the ColumnTransformer inside the Pipeline before LogisticRegression.

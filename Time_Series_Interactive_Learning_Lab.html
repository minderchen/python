01 / CONCEPT

What makes data a time series?

A date field alone does not make a dataset a time series. Repeated measurements, their order, and their timing matter.

WHAT

Observations are recorded at meaningful times, often at a regular cadence.

WHY

Past values may help explain current values; time order carries information.

HOW

Identify the entity, time column, and grain (what one row represents).

Choose the data structure

Switch between cross-sectional, time-series, and panel data.

DATA GRAIN

Daily sales · one retail chain

Each point represents one day of sales for the same process. Time order matters.

Ask three questions:
1. What does one row represent?
2. How many entities are observed?
3. Are entities observed repeatedly over time?
Key idea: Time-series methods respect the ordering of observations.

PYTHON · REPRODUCIBLE DATA GENERATION
import numpy as np
import pandas as pd

rng = np.random.default_rng(42)
dates = pd.date_range("2024-01-01", "2025-12-31", freq="D")
t = np.arange(len(dates))
weekend = (dates.dayofweek >= 5).astype(int)
values = (200 + 0.06*t + 35*weekend
          + 20*np.sin(2*np.pi*t/365.25)
          + rng.normal(0, 15, len(dates)))
ts = pd.DataFrame({"Sales": np.maximum(0, np.rint(values)).astype(int)}, index=dates)
ts.index.name = "Date"
03 / PREPARE

Dates, reindexing, and missing values

A complete calendar exposes missing observations. Filling a missing value is a separate analytical choice.

WHAT

reindex() matches data to a new date index, adding missing positions as NaN.

WHY

A missing sales record is not necessarily a day of zero sales.

HOW

Remove a date, reindex to a complete calendar, and compare repair strategies.

How should missing sales be handled?

Don't assume zero. A missing record could reflect a reporting problem, not zero sales.

ts = ts.sort_index()

aligned = incomplete.reindex(calendar)      # NaN on March 5
repaired = aligned["Sales"].interpolate(method="time")

05 / SUMMARIZE

Resampling: Change the time frequency

Downsampling combines frequent observations into fewer intervals. Upsampling creates more time positions, which may need additional values.

WHAT

Downsample daily to weekly, monthly, or quarterly; upsample coarse data to finer timestamps.

WHY

Reporting at a useful frequency clarifies business patterns and reduces chart clutter.

HOW

PYTHON · RESAMPLE & AGGREGATE
# Daily sales → month-end totals
monthly_total = ts["Sales"].resample("ME").sum()
# Daily sales → weekly average
weekly_mean = ts["Sales"].resample("W-SUN").mean()
# Explicit week boundaries
weekly = ts["Sales"].resample(
    "W-SUN", label="right", closed="right"
).sum()
# Month-end totals → daily positions; new days are NaN
upsampled = monthly_total.resample("D").asfreq()
06 / SMOOTH

Rolling windows vs. running totals

Rolling windows summarize a recent fixed period; expanding windows aggregate everything observed so far.

WHAT

Moving averages smooth short-term fluctuations; expanding sums accumulate values.

WHY

See the trend separately from day-to-day noise, and track cumulative progress.

HOW

Change the rolling window or show a running total from the same dataset.

PYTHON · ROLLING & EXPANDING
# A fixed 7-row rolling mean
ts["MA_7"] = ts["Sales"].rolling(window=7).mean()
# Include early, incomplete windows
ts["MA_7_partial"] = ts["Sales"].rolling(
    window=7, min_periods=1
).mean()
# Running total from the first observation
ts["Cumulative"] = ts["Sales"].expanding().sum()
# Equivalent for complete numeric series:
ts["Cumulative"] = ts["Sales"].cumsum()

From analysis to forecasting

Train on earlier observations. Test on later observations. Compare a simple weekly baseline with an actual fitted seasonal ARIMA model.

WHAT

Forecasting predicts values at future dates using patterns learned from historical data.

WHY

Forecasts inform inventory, staffing, budgeting, and capacity planning.

HOW

Compare held-out predictions and evaluate mean absolute error (MAE).

How the two methods work — and where SARIMA fits
Seasonal naïve repeats the last observed seven days for the forecast horizon.
SARIMA is a statistical model with autoregressive, differencing, moving-average, and seasonal terms. The SARIMA predictions in this page were fitted beforehand in Python using statsmodels on the exact embedded dataset; this browser does not refit SARIMA when controls change.
Evaluation horizon changes the number of held-out days scored, using the same original fitted forecasts. No future test values are used to train either model.
PYTHON · REAL SARIMA FORECAST
from statsmodels.tsa.statespace.sarimax import SARIMAX
train = ts["Sales"].iloc[:-56]
test = ts["Sales"].iloc[-56:]
# A simple weekly baseline
naive = pd.Series(np.resize(train.iloc[-7:].to_numpy(), len(test)), index=test.index)
# Train seasonal ARIMA only on earlier data
model = SARIMAX(train, order=(1,1,1),
    seasonal_order=(1,0,1,7),
    enforce_stationarity=False,
    enforce_invertibility=False)
fit = model.fit(disp=False)
pred = fit.get_forecast(steps=len(test)).predicted_mean
mae_naive = (test - naive).abs().mean()
mae_sarima = (test - pred).abs().mean()
print(mae_naive, mae_sarima)
This dataset and its SARIMA predictions are precomputed from a reproducible Python script, not fetched from a server. The confidence band is not displayed because a single fitted-model interval requires additional assumptions to interpret.

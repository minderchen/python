Logical Expressions

Arithmetic expressions answer how much. Logical expressions answer yes or no — and every filter, every alert threshold, every branch in a program is built from them.

Programs = Data Structures + Algorithms
Here the data structure is bool — a type with exactly two values — and the algorithms are comparison and logic.
1

The big idea: questions that return a value

A logical expression looks like a question but behaves like a calculation. Python evaluates it and hands back one of two values, which you can store, print, count or feed into a decision.

a question with an answer you can keep
sales = 12500

print(sales >= 10000)
print(sales < 5000)

is_target_hit = sales >= 10000   # store the answer
print(is_target_hit, type(is_target_hit))
True False True <class 'bool'>
HOLD ON TO THIS

True and False are values, exactly like 42 or "West". Capital letter, no quotes. "True" in quotes is a string and behaves completely differently.

2

bool: the two-value data type

WHAT

A built-in type whose entire domain is two values: True and False.

WHY

Two values is the smallest useful data structure. It is what lets a program choose, filter and count.

HOW

Produced by comparison operators, combined by and/or/not, consumed by if, while and filters.

Booleans are a numeric type underneath: True equals 1 and False equals 0. That single fact makes counting almost free, as section 11 shows.

booleans are numbers in disguise
print(True + True)          # 1 + 1
print(int(False))
print(sum([True, False, True, True]))   # counts the Trues

# the same value, three ways of getting it
print(bool(1), 12500 >= 10000, not False)
2 0 3 True True True

Two operators the poster leaves out

in and not in also return Booleans, and in analytics they replace long chains of or.

membership tests
region = "West"
core_regions = ["West", "East", "Central"]

# the long way
print(region == "West" or region == "East" or region == "Central")

# the readable way
print(region in core_regions)
print(region not in ["North", "South"])

print("est" in "Western")      # substring search

Combining conditions: and, or, not

WHAT

Three operators that take Booleans as operands and return a Boolean.

WHY

Real business rules are compound: qualified and not returned, West or Central.

HOW

and needs every part true. or needs at least one. not flips.

a bonus rule, built up in stages
sales    = 12500
profit   = 2400
region   = "West"
returned = False

hit_target   = sales >= 10000
good_margin  = profit > 2000
clean_record = not returned

print(hit_target, good_margin, clean_record)
print(hit_target and good_margin and clean_record)   # bonus?

READABILITY

Naming each condition (hit_target, good_margin) turns an unreadable one-liner into something a manager could review. The Booleans become named data, which is exactly the "data structures" half of the formula.

De Morgan's laws: rewriting negations

Negating a compound condition flips both the parts and the connector. Getting this wrong quietly changes which records you keep.

XOR IN PRACTICE

Python has no xor keyword for Booleans — a != b does the job. It answers "exactly one of these, not both", useful for reconciliation checks where a record should appear in one system or the other but never in both.

7

Precedence: what runs first

One expression can mix arithmetic, comparison and logic. Python resolves them in a fixed order, and the order is not left to right.

Step through an evaluation

With sales = 8200, profit = 1900, region = "West":

the parentheses change who qualifies
sales, profit, region = 8200, 1900, "West"

# and binds tighter, so this reads: (sales >= 10000 and profit > 2000) or region == "West"
a = sales >= 10000 and profit > 2000 or region == "West"

# a very different rule
b = sales >= 10000 and (profit > 2000 or region == "West")

print(a)
print(b)
True False
SILENT ERROR

Both lines run without complaint. One says "any West rep qualifies"; the other says "only high-selling reps qualify, and West is an alternative to margin". Mixing and with or without parentheses is one of the most common causes of a wrong report.

Chained comparisons

Python allows a range test written the way it is written in mathematics. Most languages do not.

range checks
sales = 8200

print(5000 <= sales <= 15000)              # chained, reads naturally
print(sales >= 5000 and sales <= 15000)    # identical meaning

# useful for banding
score = 72
print(70 <= score < 80)                    # a "C" band, upper bound excluded
True True True
8

Truthiness: when non-Booleans act like Booleans

WHAT

Python can treat any value as a condition. Some values count as false, everything else counts as true.

WHY

It makes "is there any data here?" checks short — and it makes some bugs invisible.

HOW

Empty things and zero are falsy. Test with bool(x) if you are unsure.

Falsy valuesTruthy values
0   0.0   ""   []   {}   ()   set()   None   False any other number, any non-empty string, list, dict or set
checking for data before working on it
records = []
region  = ""
discount = 0

print(bool(records), bool(region), bool(discount))
print(bool([0]), bool("0"), bool(0.1))   # careful: these are all truthy

if not records:
    print("No records loaded — check the file path.")

# the idiomatic emptiness check
sales = [1200, 980, 1450]
if sales:
    print("Rows:", len(sales))
False False False True True True No records loaded — check the file path. Rows: 3
THE ZERO TRAP

if discount: is False when the discount is genuinely 0, which is a real value, not missing data. When zero is legitimate, test explicitly: if discount is not None:.

9

Short-circuit evaluation

Python stops as soon as the answer is certain. With and, a false left operand settles it. With or, a true left operand settles it. The right operand is never evaluated.

the guard pattern
revenue = 0
profit  = 0

# Without the guard this raises ZeroDivisionError
# print(profit / revenue > 0.2)

# With it, the division never runs
print(revenue != 0 and profit / revenue > 0.2)

# The same idea for missing data
record = {"rep": "Ada"}
print("amount" in record and record["amount"] > 1000)
False False
ORDER MATTERS NOW

Put the cheap or protective test on the left. revenue != 0 and profit / revenue > 0.2 is safe; swap the operands and it crashes. With and/or, order is not just style.

and and or return operands, not just Booleans

a useful side effect
region = ""
print(region or "Unassigned")     # falls back when region is empty

name = "Ada"
print(name or "Unknown")

print(0 and 99)      # stops at 0, returns 0
print(5 and 99)      # passes the first, returns the second
Unassigned Ada 0 99

Where beginners slip

= is not ==

= assigns a value. == asks a question. Using = inside an if is a syntax error in Python, which is a kindness — in some languages it silently overwrites your data.

x == 1 or 2 does not mean what it looks like

the most convincing wrong condition in Python
quarter = 4

print(quarter == 1 or 2)          # always truthy — 2 is a truthy value!
print(quarter == 1 or quarter == 2)
print(quarter in (1, 2))          # the readable fix
True False False
WHY IT HAPPENS

quarter == 1 or 2 is read as (quarter == 1) or (2). Since 2 is truthy, the whole thing is always true. Every record passes the filter and nobody notices.

is is not ==

identity versus equality
a = [1, 2, 3]
b = [1, 2, 3]

print(a == b)      # same contents
print(a is b)      # two separate objects in memory

value = None
print(value is None)     # correct way to test for None
print(value == None)     # works, but not idiomatic
True False True True
RULE OF THUMB

Use is only with None, True and False. For every other comparison, use ==.

Floats and ==

the arithmetic trap resurfaces
print(0.1 + 0.2 == 0.3)
print(round(0.1 + 0.2, 10) == 0.3)
print(abs((0.1 + 0.2) - 0.3) < 1e-9)   # tolerance comparison
False True True

Don't compare a Boolean to True

if is_active == True: works, but if is_active: says the same thing and cannot go wrong. Similarly, prefer if not is_active: over if is_active == False:.

11

Analytics lab: Booleans as data

This is where the formula pays off. The list of dictionaries is the data structure; the conditions are the algorithm; the Booleans they produce become new data you can count, filter and summarise.

bonus_qualification.py
# ---- DATA ----
sales = [
    {"rep": "Ada",  "region": "West",    "amount": 12500, "profit": 2400, "returned": False},
    {"rep": "Bo",   "region": "East",    "amount":  8200, "profit": 1900, "returned": False},
    {"rep": "Cruz", "region": "West",    "amount": 15100, "profit": 1800, "returned": True},
    {"rep": "Dae",  "region": "North",   "amount":  4900, "profit":  600, "returned": False},
    {"rep": "Eli",  "region": "Central", "amount": 10000, "profit": 2100, "returned": False},
]

# ---- PROCESS ----
def qualifies(s):
    return s["amount"] >= 10000 and s["profit"] > 2000 and not s["returned"]

winners    = [s["rep"] for s in sales if qualifies(s)]
flags      = [qualifies(s) for s in sales]      # a list of Booleans
high_value = sum(s["amount"] >= 10000 for s in sales)

# ---- OUTPUT ----
print("Bonus winners :", winners)
print("Flags         :", flags)
print("High value    :", high_value, "of", len(sales))
print("Any returns?  :", any(s["returned"] for s in sales))
print("All profitable:", all(s["profit"] > 0 for s in sales))
print("West or Central:", [s["rep"] for s in sales if s["region"] in ("West", "Central")])
Bonus winners : ['Ada', 'Eli'] Flags : [True, False, False, False, True] High value : 3 of 5 Any returns? : True All profitable: True West or Central: ['Ada', 'Cruz', 'Eli']
THE BRIDGE TO PANDAS

That list of flags — [True, False, False, False, True] — is a Boolean mask. In pandas you write df[df["amount"] >= 10000] and the library builds exactly this list for you, then keeps the rows where it is True. Everything on this card transfers directly.

Counting patterns worth memorising

QuestionExpressionReturns
How many rows match?sum(cond for row in data)an int
Does at least one match?any(cond for row in data)a bool
Do all of them match?all(cond for row in data)a bool
Which rows match?[row for row in data if cond]a filtered list
What proportion match?sum(...) / len(data)a float

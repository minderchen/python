Mathematical Expressions

Every revenue figure, margin percentage and growth rate you will ever compute starts here: values joined by operators to produce a new value. Seven symbols do almost all the work.

Programs = Data Structures + Algorithms
An expression is that formula in miniature: operands are the data, operators are the algorithm.
1

The big idea: data meets process

Niklaus Wirth's formula says a program is data structures plus algorithms. That sounds abstract until you look at a single line of Python:

the smallest possible program
revenue = 1250 * 29.99
print(revenue)
37487.5

The numbers 1250 and 29.99 are data. The * is the process applied to that data. The result is new data, stored in a variable so a later step can use it. Scale that pattern up and you have a pricing engine, a forecast model, or a pandas pipeline.

HOLD ON TO THIS

An expression produces a value. A statement performs an action. 1250 * 29.99 is an expression; revenue = 1250 * 29.99 is a statement that contains one.

2

Anatomy of an expression

WHAT

A combination of operands (values or variables) and operators that Python reduces to exactly one value.

WHY

Every calculated column, KPI and model input is an expression. Reading them accurately is the core analyst skill.

HOW

Python evaluates inner to outer, following precedence rules, replacing each sub-expression with its value until one remains.

Operands do not have to be literal numbers. Any of these are valid operands, because each one is itself an expression that produces a number:

operands come in many forms
units = 1250
price = 29.99
discount_rate = 0.10

# a literal
print(1250 * 29.99)

# variables
print(units * price)

# a nested expression as an operand
print(units * (price * (1 - discount_rate)))

# a function call as an operand
print(round(units * price, 2))
37487.5 37487.5 33738.75 37487.5

The seven arithmetic operators

These seven symbols cover essentially all numeric work in analytics. Read the table, then notice the two rows that surprise most beginners.

THE TWO SURPRISES

10 / 5 gives 2.0, not 2. In Python 3 the / operator always produces a float, so a division result can never be assumed to be a whole number type.

% is not a percent sign. It returns the remainder after division. To compute a percentage you multiply by 100.

Every operator also works with variables and mixed types, which is how you will nearly always meet them in real code:

all seven, in a business setting
units = 1250
price = 29.99
cost = 18.50
cases_per_pallet = 96

print(price + 2.00)              # add a shipping surcharge
print(price - cost)              # margin per unit
print(units * price)             # gross revenue
print(units / 12)                # average units per month
print(1.08 ** 5)                 # growth factor over 5 years
print(units % cases_per_pallet)  # units left after full pallets
print(units // cases_per_pallet) # number of full pallets

SPOTTED IT?

price - cost printed 11.489999999999998 rather than 11.49. That is not a bug in Python. Section 9 explains it.

Operator playground

Change the two operands and watch all seven operators respond. Try a = 7, b = 2, then a = -7, b = 2, then set b to zero.

TRY THIS

Set a = -7 and b = 2. You get -7 // 2 → -4, not -3. Floor division rounds down toward negative infinity, not toward zero. This matters whenever you bucket values that can go negative, such as variance to budget.

The division trio: / vs // vs %

WHAT

Three operators answer three different questions about the same division.

WHY

Shipping, staffing and batching problems are almost always "how many whole units, and what is left over".

HOW

/ gives the exact share, // gives the whole groups, % gives the remainder.

6

Exponentiation at work

WHAT

a ** b multiplies a by itself b times. A fractional exponent takes a root.

WHY

Compounding is multiplicative, not additive. Growth over n periods is a power, and CAGR is its inverse.

HOW

Future value: pv * (1 + r) ** n. Growth rate: (end / start) ** (1 / n) - 1.

compounding and CAGR
opening = 10000
rate    = 0.08
years   = 5

future_value = opening * (1 + rate) ** years
print("Future value:", round(future_value, 2))

# The inverse: revenue grew from 1.0M to 1.5M over 3 years.
start, end, n = 1_000_000, 1_500_000, 3
cagr = (end / start) ** (1 / n) - 1
print("CAGR:", round(cagr * 100, 2), "%")

# A fractional exponent is a root
print(16 ** 0.5)   # square root
print(27 ** (1/3)) # cube root
Future value: 14693.28 CAGR: 14.47 % 4.0 3.0
RIGHT TO LEFT

** is the one operator that groups from the right. 2 ** 3 ** 2 is 2 ** (3 ** 2) = 2 ** 9 = 512, not (2 ** 3) ** 2 = 64. When in doubt, add parentheses.

7

Order of operations

WHAT

A fixed ranking that decides which operator runs first when several appear in one expression.

WHY

A misread precedence produces a number that looks plausible and is silently wrong. No error is raised.

HOW

Work down the pyramid. Within one level, go left to right — except **, which goes right to left.

Step through an evaluation

Watch Python collapse one expression to one value. Each step replaces the highlighted sub-expression with its result.

Why parentheses are not optional in practice

the same numbers, two very different answers
units, price, discount = 1250, 29.99, 0.10

# WRONG: only the discount is subtracted from the price... or is it?
wrong = units * price - discount
print(wrong)

# RIGHT: discount the price first, then multiply
right = units * (price * (1 - discount))
print(round(right, 2))

# average of three regions
a, b, c = 120, 340, 210
print(a + b + c / 3)     # only c is divided
print((a + b + c) / 3)   # the actual mean
37487.4 33738.75 463.0 223.33333333333334
HABIT WORTH BUILDING

If an expression mixes more than two precedence levels, parenthesise it even where the rules already give you the right answer. You write a line once and read it twenty times.

ANALYTICS TRAP

Values read from CSV files, web forms and APIs arrive as strings. "250" * 2 does not fail — it silently returns "250250". Convert with int() or float() before any arithmetic, and check with type() when a total looks strange.

9

Where beginners slip

Floats do not store decimals exactly

Computers store numbers in binary. Just as 1⁄3 cannot be written exactly in decimal, 0.1 cannot be written exactly in binary. Tiny errors accumulate.

the classic surprise
print(0.1 + 0.2)
print(0.1 + 0.2 == 0.3)

# Fix 1: round at the point of display or comparison
print(round(0.1 + 0.2, 2))
print(round(0.1 + 0.2, 10) == 0.3)

# Fix 2: for money, use Decimal
from decimal import Decimal
print(Decimal("0.1") + Decimal("0.2"))
0.30000000000000004 False 0.3 True 0.3
RULE

Never test floats with ==. Round first, or compare the difference against a small tolerance. For currency in production code, use Decimal.

Division by zero stops the program

guard the denominator
revenue = 0
profit  = 0

# margin = profit / revenue   →  ZeroDivisionError: division by zero

margin = profit / revenue if revenue != 0 else None
print("Margin:", margin)
Margin: None

Truncation is not rounding

// and int() chop the fraction off; round() goes to the nearest value. Using the wrong one understates every result in a column.

7.9 handled three ways
x = 7.9
print(x // 1)     # floor: down
print(int(x))     # truncate toward zero
print(round(x))   # nearest

y = -7.9
print(y // 1, int(y), round(y))  # floor and truncate now disagree
7.0 7 8 -8.0 -7 -8

Shorthand assignment

Once a variable exists, you often update it using its own current value. Python has a compact form for that, and you will meet it constantly inside loops.

ShorthandEquivalent toTypical use
total += xtotal = total + xrunning sum across rows
budget -= costbudget = budget - costdrawing down a balance
value *= 1.08value = value * 1.08applying growth each period
pool /= 4pool = pool / 4splitting across quarters
count //= 2count = count // 2halving, whole units only
running totals over a sales list
daily_sales = [1200.50, 980.00, 1450.75, 1100.25]

total = 0
for amount in daily_sales:
    total += amount

print("Total:", round(total, 2))
print("Average:", round(total / len(daily_sales), 2))

# compounding a balance year by year
balance = 10000
for year in range(5):
    balance *= 1.08
print("After 5 years:", round(balance, 2))
Total: 4731.5 Average: 1182.88 After 5 years: 14693.28
CONNECTS BACK

The loop is the algorithm, the list is the data structure, and += is the expression that joins them. This is the whole Wirth formula in six lines.

11

Analytics lab: one product line, end to end

Every operator from the table appears here doing real work. Read the code first and predict each output before revealing it.

product_line_analysis.py
# ---- DATA (the data structure) ----
units_sold     = 1250
unit_price     = 29.99
unit_cost      = 18.50
fixed_costs    = 5000
prior_revenue  = 32000
units_per_case = 24

# ---- PROCESS (the algorithm) ----
revenue      = units_sold * unit_price
cogs         = units_sold * unit_cost
gross_profit = revenue - cogs
margin_pct   = gross_profit / revenue * 100
growth_pct   = (revenue - prior_revenue) / prior_revenue * 100

contribution   = unit_price - unit_cost
breakeven_raw  = fixed_costs / contribution
breakeven_units = int(breakeven_raw // 1) + 1   # partial units don't sell

full_cases  = units_sold // units_per_case
loose_units = units_sold %  units_per_case

# ---- OUTPUT (the interface) ----
print("Revenue        :", round(revenue, 2))
print("COGS           :", round(cogs, 2))
print("Gross profit   :", round(gross_profit, 2))
print("Margin %       :", round(margin_pct, 2))
print("Growth vs prior:", round(growth_pct, 2))
print("Break-even     :", breakeven_units, "units")
print("Cases / loose  :", full_cases, "/", loose_units)
Revenue : 37487.5 COGS : 23125.0 Gross profit : 14362.5 Margin % : 38.31 Growth vs prior: 17.15 Break-even : 436 units Cases / loose : 52 / 2
READ THE CHOICES

breakeven_raw is 435.16 units. Rounding would give 435, which does not cover fixed costs. Flooring and adding one gives 436 — the first unit that actually breaks even. Choosing between round(), // and int() is a business decision, not a syntax decision.

THE THROUGH-LINE

Expressions are where data structures and algorithms first touch. Choose the operator that matches the question you are actually asking, keep the types straight, and make the order explicit. Everything from a pandas calculated column to a machine learning loss function is built from exactly these pieces.

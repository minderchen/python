Python for Business Analytics: pandas processes

Method chaining: each method works on the result of the one before it

Read a chain left to right. Every .method() returns a new object, and the next dot calls a method on that returned object, not on the original data.

Beside each line: the object it hands to the next line.

What

A chain is a relay: the return value is the baton

Method chaining means calling several methods one after another in a single expression, joined by dots. It works because each method returns an object, and Python immediately calls the next method on that returned object.

In the series framework, Application = Data + Process + UI, a chain is the Process part written as a pipeline: data goes in on the left, and each method transforms it one step further.

Warm-up with a string you already know

A messy region label from a CSV export needs cleaning. Press Run next method and watch what each method receives and what it gives back.


  

  

    
    
    
  


  
Each dot is applied to the value returned by everything to its left. .title() never sees the original text with spaces; it only sees what .strip() handed it.


  
How Python groups a DataFrame chain

  
The same rule works for a pandas DataFrame. Python evaluates the innermost, leftmost piece first, then wraps the next method around its result.

  

  
  

  
Written out with brackets, Python reads it as (sales.dropna()).head(3).







  
Why

  
Why chain instead of saving every step?

  
Both versions below produce the same top 3 orders over $800. The first stores every in-between result in its own variable. The second passes each result straight to the next method.

   order_id region  product  revenue
0       101   West   Laptop   3600.0
7       108   East   Laptop   2400.0
1       102   East  Monitor   1250.0

    
Identical. The row labels 0, 7, 1 are the original index values from sales; sorting and filtering keep them.

  


  

    
Reads like a recipe
Top to bottom: clean, filter, sort, take the top 3. The code order matches the order of the business steps.

    
No clutter
Names like step2 are easy to mix up. Using step1 where you meant step2 is a silent bug.

    
Original data stays safe
Each method returns a new object, so sales itself is never changed by the chain.

  

  

    
The trade-off
You can't see the middle results as easily. If a long chain gives a surprising answer, cut it short (or comment out the later lines) and look at what comes back. Break a chain into named pieces when you need to reuse a middle result or when it grows past about six or seven steps.

How

  
Write it on one line or across many

  
Python does not care how you lay the chain out, as long as it knows the expression is not finished at the end of a line. Toggle the layout to see the same code both ways.

  

    
    
    
  

  

  


  
Rules for multi-line chains

  
    
    
  • Wrap the whole chain in parentheses. Inside ( ), Python keeps reading until the closing bracket, so line breaks are allowed. Recommended
    • 
    
  • Start each line with the dot. Putting .method() at the start makes each step easy to scan, reorder, or comment out.
    • 
    
  • Comments are fine inside the parentheses, one per line, to say what each step does.
    • 
    
  • A backslash \ also works, but it must be the very last character on the line. A single space after it is a SyntaxError, and you can't add a comment after it. Works, but fragile
    • 
    
  • No wrapper at all fails. Python treats the line break as the end of the statement. Error
    • 
  

  
  

    

    
  File "report.py", line 2
    .dropna()
    ^
SyntaxError: invalid syntax

    
Python finished the statement at result = sales, then found a line that starts with a dot. If the dot line is indented, the message is IndentationError: unexpected indent instead.

  







  
How

  
When a chain breaks, check what was returned

  
Almost every chain error comes from the same place: the next method does not exist on the object the previous step returned. Open each case to see the error and the fix.


  

    The previous step returned a single number
    

      

      
AttributeError: 'numpy.float64' object has no attribute 'sort_values'

      
.sum() on a column returns one number (a numpy.float64). A number has nothing to sort, so it has no .sort_values() method. Sort before you total, or group first so .sum() returns a Series.

    

  

  

    Using inplace=True in the middle of a chain
    

      

      
AttributeError: 'NoneType' object has no attribute 'head'

      
With inplace=True, pandas changes sales directly and returns None. The chain then tries None.head(). Leave inplace out when chaining; you want the returned object.

    

  

  

    A space after the backslash
    

      
result = sales \␣
    .dropna()

      
SyntaxError: unexpected character after line continuation character

      
The ␣ marks an invisible trailing space. It's easy to miss and hard to see in an editor, which is why parentheses are the safer choice.

    

  

  
Debugging habit: when a chain fails, run it up to the step before the error and check the result with type(). That tells you which methods are allowed next.

Working with DataFrames

A DataFrame is the table at the center of almost every pandas program: labeled rows, labeled columns, mixed data types — built out of a simpler piece, the Series. This walkthrough starts with that building block, then builds up the idea piece by piece — what each feature is, why it exists, and how you use it — with short checks along the way.

01

What is a Series?

what

A Series is a one-dimensional, labeled array of data — a single column of values, where every value has a label attached to it called the index.

why

A plain Python list holds values but no labels — you can only ever ask for "item 2." A Series is the smallest building block in pandas that adds that label, and it's what every column of a DataFrame turns out to be underneath. Starting here makes the table structure much easier to grasp.

how 
import pandas as pd

ages = pd.Series([25, 30, 28, 35], name="Age")
print(ages)
OUT
0 25 1 30 2 28 3 35 Name: Age, dtype: int64

The left-hand column (0, 1, 2, 3) is the index — like a dictionary key for each value. You can look up ages[1] and get back 30.

02

What is a DataFrame?

what

A DataFrame is a 2-dimensional table made of several Series lined up side by side, all sharing the same index. Each column can hold its own data type (numbers, text, dates) — but every column is, underneath, just a Series.

why

Real data is rarely a single column — you need a name, an age, and a city together in one record. Bundling several Series under a shared index gives you exactly that, while every operation that works on a lone Series (.mean(), .apply(), ...) still works column-by-column inside the table.

how

Pulling a single column back out of a DataFrame returns you to a Series — the relationship runs both ways:

ages = df["Age"]
print(type(ages))
OUT
<class 'pandas.core.series.Series'>

03

Creating a DataFrame

what

The most common constructor takes a Python dictionary, where each key becomes a column name and each value (a list) becomes that column's data.

why

You rarely start with a CSV in a tutorial or a quick script — you start with data you already have in Python. The dict constructor is the fastest bridge from "some lists I have" to "a table I can query."

how 
import pandas as pd

data = {
    "Name": ["Alice", "Bob", "Carol", "Dave"],
    "Age": [25, 30, 28, 35],
    "City": ["New York", "Los Angeles", "San Francisco", "Chicago"]
}

df = pd.DataFrame(data)
print(df)
OUT
Name Age City 0 Alice 25 New York 1 Bob 30 Los Angeles 2 Carol 28 San Francisco 3 Dave 35 Chicago

Notice the leftmost unlabeled column — that's the auto-generated index (0, 1, 2, 3), the same idea you just saw on a lone Series, now shared across every column. You can also supply your own with index=[...].

quick check

In pd.DataFrame(data) where data is a dictionary, what do the dictionary's keys become?

04

Selecting data

what

pandas gives you two dedicated accessors for rows: .loc selects by label, and .iloc selects by integer position. You can also filter rows with a boolean condition.

why

"Label" and "position" aren't always the same thing — especially after sorting or filtering, where the index no longer runs 0, 1, 2... in order. Having two explicit accessors avoids ambiguity about which one you mean.

how 
df.loc[0]              # row labeled 0
df.iloc[0]             # row in position 0 (the first row)
df.loc[0, "Name"]      # label-based: row 0, column "Name"

# filter with a condition
adults = df[df["Age"] >= 30]
OUT
Name Age City 1 Bob 30 Los Angeles 3 Dave 35 Chicago
quick check

05

Adding, modifying & dropping columns

what

Columns can be assigned like dictionary keys, transformed with vectorized math, or computed with .apply() for anything more custom.

why

Real analysis is rarely just reading data — it's deriving new information from it (a total, a flag, a category). Treating columns like assignable variables keeps that process quick and readable.

how 
df["Senior"] = df["Age"] >= 30
df["Age"] = df["Age"] + 1
df["Name_Upper"] = df["Name"].apply(lambda x: x.upper())

df = df.drop(columns=["Senior"])
06

Sorting & grouping

what

sort_values() reorders rows by a column. groupby() splits the DataFrame into groups by a column's values, applies an aggregation, then combines the results back into one table.

why

Most real questions about data are group questions — "average age per city," "total sales per region." groupby exists so you don't have to write that loop by hand.

how 
df.sort_values("Age", ascending=False)

groupby follows a simple three-step pattern:

1
Split

Divide the data into groups based on one or more shared values — e.g. group sales records by region.

→
2
Apply

Perform a calculation separately within each group — e.g. the total, average, or count of orders per region.

→
3
Combine

Put the results from all groups back into one organized result.

df.groupby("region")["sales"].sum()
  • Split — separate rows by region
  • Apply — add up sales within each region
  • Combine — return one total-sales result for each region
quick check

07

Handling missing data

what

Missing values show up as NaN. pandas gives you tools to find them, drop them, or fill them in.

why

Almost no real dataset is complete. Deciding what to do with the gaps — drop the row, drop the column, or fill with a default — is a normal, necessary step before any analysis.

how 
df.isna()             # boolean mask of missing values
df.dropna()            # drop rows with any missing values
df.fillna(0)            # replace missing values with 0

A field guide to Python control flow

Every program is built from three moves.

Code either runs in order, chooses a path, or repeats itself. That's it — sequence, selection, and repetition are the entire vocabulary of control flow. Everything else in Python is a variation on these three.

01

Sequence

The default. Statements run top to bottom, in the order they're written, each one exactly once.

flow
code
price = 40
tax = price * 0.08
total = price + tax
print(total)
seq_example.py
>>> 43.2
Why does order matter here?▸

Each line depends on the one before it: tax needs price to already exist, and total needs both. Swap the last two lines and Python raises a NameError — you'd be asking for tax before it exists.

Sequence is invisible when it works, which is most of the time. It only becomes interesting once a line's outcome depends on something that isn't fixed — which is exactly where selection comes in.

02

Selection

The program checks a condition and picks one branch to run. if tests, elif offers more tests, else catches everything left over.

flow
code
score = 82

if score >= 90:
    grade = "A"
elif score >= 70:
    grade = "B"
else:
    grade = "F"

print(grade)
selection_example.py
>>> B
What if I change score to 95?▸

Only the first true branch runs. With score = 95, the if condition is already true, so Python assigns "A" and skips the elif and else entirely — it never even checks whether score >= 70.

That's why branch order matters: if you wrote elif score >= 70 before if score >= 90, a 95 would incorrectly land in the "B" branch, because 95 also satisfies >= 70 and Python stops at the first match.

Truthy and falsy — selection without comparisons▸

if doesn't require a comparison like == or >=. It accepts anything and asks whether Python considers it true. Empty things — 0, "", [], None — count as false. Everything else counts as true.

cart = []

if cart:
    print("Checking out...")
else:
    print("Cart is empty")
truthy_example.py
>>> Cart is empty
03

Repetition

The same block runs more than once. for repeats over a known sequence; while repeats until a condition turns false.

flow — for
code
for name in ["Ada", "Grace", "Kai"]:
    print(f"Hi, {name}")
for_example.py
>>> Hi, Ada Hi, Grace Hi, Kai
code — while
battery = 100

while battery > 0:
    battery -= 25
    print(f"Battery: {battery}%")
while_example.py
>>> Battery: 75% Battery: 50% Battery: 25% Battery: 0%
when to use which
for
You know what you're iterating over — a list, a string, a range. The count is baked into the data.
while
You don't know how many iterations it'll take — you're waiting for a condition to change.
Escaping early: break, continue, pass▸

break exits the loop immediately. continue skips the rest of the current pass and jumps to the next one. pass does nothing — a placeholder where Python's syntax requires a statement.

for n in range(10):
    if n == 5:
        break
    if n % 2 == 0:
        continue
    print(n)
loop_control.py
>>> 1 3
04

Scope and code blocks

Python doesn't use { } to mark a block — it uses indentation. How deep a line is indented decides which structure it belongs to, and that nesting decides where a variable can be seen.

indentation = block membership
for student in class_list:
if student.grade >= 90:
honors.append(student)
print(len(honors))   # back to zero indent — outside the loop
What happens if the indentation is wrong?▸

Python raises an IndentationError before your code even runs. This isn't a style nitpick the way it is in most languages — indentation is the syntax that defines a block. Two spaces or four, it doesn't matter, but it must be consistent within the same block.

scope: who can see x?
global scope
x = "outer"
function scope
x = "inner"
Inside the function, this local x shadows the outer one — the function never touches the outer variable.
code
x = "outer"

def show():
    x = "inner"
    print(x)

show()
print(x)
scope_example.py
>>> inner outer
Loops don't create a new scope for varaiables — if and for leak variables▸

Unlike functions, a for loop or an if block does not get its own scope for variables. A variable assigned inside one is still visible after it ends — a common surprise for people coming from other languages.

for i in range(3):
    last = i

print(last)  # still works — 2
leak_example.py
>>> 2
05

Nested loops

A loop body can contain another loop. The inner loop runs to completion for every single pass of the outer one — that's the whole mental model, but it's worth watching happen.

code — 3×3 grid
for row in range(3):
    for col in range(3):
        print(f"({row},{col})", end=" ")
    print()
nested_example.py
>>> (0,0) (0,1) (0,2) (1,0) (1,1) (1,2) (2,0) (2,1) (2,2)
trace it step by step
row=0, col=0
How many times does the inner loop actually run?▸

The outer loop runs 3 times. For each of those, the inner loop runs its full 3 iterations. Total: 3 × 3 = 9 print calls — one per cell in the grid above. Nest a third loop and it becomes 3 × 3 × 3 = 27, which is why deeply nested loops get expensive fast.

break inside a nested loop only breaks the inner one▸

This trips people up constantly: break only exits the loop it's directly written inside. To stop the outer loop too, you need a flag, an exception, or restructuring into a function so you can return.

for row in range(3):
    for col in range(3):
        if col == 1:
            break  # only exits the inner loop
        print(f"({row},{col})")
nested_break.py
>>> (0,0) (1,0) (2,0)
Nested loops combined with selection: filtering a grid▸

This is where all three structures meet in one piece of code: repetition (the two for loops) drives selection (the if), and everything still runs in sequence line by line.

for row in range(1, 4):
    for col in range(1, 4):
        product = row * col
        if product % 2 == 0:
            print(f"{row}×{col}={product} (even)")
combined_example.py
>>> 1×2=2 (even) 2×1=2 (even) 2×2=4 (even) 2×3=6 (even) 3×2=6 (even)
Sequence runs it, selection chooses it, repetition repeats it — every Python program is some arrangement of the three.

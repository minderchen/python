First built-in

len() — Finding the Length of an Object

len() is probably the built-in you'll type most often. It's worth understanding exactly what it is — and isn't.

02 len() is a function, not a list method click to expand +
len_basic.pypython 3
fruits = ["apple", "banana", "cherry"]
print(len(fruits))
3

A common early mistake is trying to call it as a method — it isn't one:

len_is_not_a_method.pypython 3
print(fruits.len())
AttributeError: 'list' object has no attribute 'len'

Under the hood: the __len__() connection

len() doesn't have its own separate way of measuring every type. Instead, it calls a special method that the object itself defines: __len__().

dunder_len.pypython 3
print(len(fruits))          # the usual way
print(fruits.__len__())    # what len() does internally
3 3

Both lines give the same answer, because len(fruits) is really just Python calling fruits.__len__() for you, with friendlier syntax. This is also why len() works on so many different types — each one implements its own __len__().

Why len() doesn't work on an integer

len() measures how many items something contains. A number like 42 doesn't contain items — it isn't a collection, so it has no __len__() to call.

len_on_int.pypython 3
len(42)
TypeError: object of type 'int' has no len()

A key distinction

Built-in Functions vs. Methods

Both do things to objects — but the syntax, and where the capability "lives," is different.

04 function(object) vs. object.method() click to expand +
BUILT-IN FUNCTION
len(aList)

The object is passed into the function as an argument. len isn't attached to any particular object.

METHOD
aList.append(10)

The function is attached to the object itself, called with dot notation. Only objects of that class have it.

function_vs_method.pypython 3
aList = [3, 1, 2]

print(len(aList))     # function(object) — len doesn't belong to aList
aList.append(10)     # object.method() — append belongs to aList
print(aList)
3 [3, 1, 2, 10]

Rule of thumb: if you see something(x), it's probably a built-in function. If you see x.something(), it's a method that belongs to x's class.

sum() — Adding Values

sum() adds up every item in a collection of numbers. Try it across a few types below.

05 sum() across types, and pairing it with len() click to expand +

sum() and len() answer different questions — sum() totals the values, len() counts how many there are. You need both to get an average.

I/O

Input and Output Functions

input() and print() are how your program talks to a person. One catch trips up almost everyone at first.

08 input() always returns a string click to expand +

Type a number below to simulate what a person would type at input(), then try both versions of the code.

type a value and pick a version above ↑
input_demo.pypython 3
age = input("How old are you? ")   # age is ALWAYS a string, even if you type "25"
print(age + 1)                       # TypeError — can't add int to str

age = int(input("How old are you? "))  # convert immediately
print(age + 1)                       # works — real math now

This is one of the most common early bugs: forgetting that whatever a person types — even "25" — arrives as text, not a number, until you convert it with int() or float().

Looping smarter

enumerate() with Lists

When you need both the position and the value while looping, enumerate() gives you both in one pass.

10 Stepping through enumerate() — sales by day click to expand +

sales = [1200, 950, 1600, 800, 1400] — step through the loop one iteration at a time.

enumerate_demo.pypython 3
sales = [1200, 950, 1600, 800, 1400]

for day, amount in enumerate(sales, start=1):
    print(f"Day {day}: ${amount}")

start=1 shifts the counter to begin at 1 instead of 0 — purely for human-friendly display; the list itself is still zero-indexed underneath.

11 enumerate() vs. range(len(...)) click to expand +

Both loops below produce identical output — one is just more Pythonic.

TRADITIONAL — range(len(...))
for i in range(len(sales)):
    print(i, sales[i])
0 1200 1 950 2 1600 3 800 4 1400
MORE PYTHONIC — enumerate()
for i, sale in enumerate(sales):
    print(i, sale)
0 1200 1 950 2 1600 3 800 4 1400

The enumerate() version never has to index into sales manually with sales[i] — it hands you the value directly, alongside the position. Same result, less room for an off-by-one mistake.

Foundation

Variables & Data Types

Variables are labeled containers for values. The data type tells Python (and you) what kind of value is inside, and what operations make sense on it. Click a sheet below to unroll it.

01 Variables & the four core data types click to expand +

A variable is created the moment you assign it a value with =. Python figures out the type automatically — this is called dynamic typing.

sales_basics.pypython 3
# four core types, framed as a sales record
product_name = "Wireless Mouse"   # str  — text
unit_price   = 24.99               # float — decimal number
units_sold   = 318                 # int   — whole number
in_stock     = True                # bool  — True / False

revenue = unit_price * units_sold
print(f"Revenue for {product_name}: ${revenue:,.2f}")
Revenue for Wireless Mouse: $7,946.82

Why it matters here

  • str — product names, customer IDs, region labels. Anything that's text, even if it looks numeric (a ZIP code stored as text won't accidentally get summed).
  • int / float — units sold, prices, revenue. Use float whenever decimals matter (money, percentages).
  • bool — flags like in_stock, is_returning_customer — the output of a comparison, and the fuel for control flow (next section).

Type conversion — a real gotcha

Data imported from a CSV or web form often arrives as strings, even when it "looks like" a number. You have to convert it explicitly:

type_conversion.pypython 3
raw_price = "24.99"       # came from a spreadsheet cell — it's a string
price = float(raw_price)   # now it's a real number you can do math with
print(price * 2)
49.98 # Without float(): raw_price * 2 would give "24.9924.99" (string repetition), not math!

Logic

Control Flow

Control flow is how a program makes decisions and repeats work — the "algorithm" side of the formula. Two building blocks cover almost everything: conditionals (branch) and loops (repeat).

02 if / elif / else — branching decisions click to expand +

Indentation is not a style choice in Python — it is the syntax that defines which lines belong to which branch.

customer_tier.pypython 3
lifetime_value = 18500

if lifetime_value >= 20000:
    tier = "Platinum"
elif lifetime_value >= 10000:
    tier = "Gold"
else:
    tier = "Standard"

print(f"Customer tier: {tier}")
Customer tier: Gold

Python checks conditions top to bottom and stops at the first True one — so order matters. Comparison operators (==, !=, >=, <...) and logical operators (and, or, not) are what you build these conditions from.

03 for / while — repeating over data click to expand +

for loops step through a known collection (a list of monthly sales, a set of customer IDs). while loops repeat until a condition becomes false — useful when you don't know the count in advance.

monthly_growth.pypython 3
monthly_sales = [12000, 15500, 13800, 17200]

for i, month_total in enumerate(monthly_sales, start=1):
    flag = "⚠ dip" if month_total < 14000 else "ok"
    print(f"Month {i}: ${month_total:,}  ({flag})")
Month 1: $12,000 (⚠ dip) Month 2: $15,500 (ok) Month 3: $13,800 (⚠ dip) Month 4: $17,200 (ok)

Notice the loop combines both halves of the formula: monthly_sales is the data structure (a list); the for loop + inline if/else is the algorithm operating on it.

Organization

Built-in Data Structures

This is the "data structures" half of the formula made concrete. Python ships with four core containers. Picking the right one is often what makes an analytics script fast, correct, and readable — instead of slow and buggy.

04 list, tuple, set, dict — quick reference click to expand +
StructureOrdered?Changeable?Duplicates?Business analytics use
listYesYesYes A time series of monthly revenue; rows read from a file, in order.
tupleYesNoYes A fixed record that shouldn't change, e.g. ("Q1", 2026) as a reporting period key.
setNoYesNo Deduplicating customer IDs; fast membership checks ("has this customer ordered before?").
dictYes*YesKeys: no A customer record looked up by ID — {"name": ..., "region": ..., "ltv": ...}.

*Since Python 3.7, dicts preserve insertion order — but you still look items up by key, not position.

containers.pypython 3
# list — ordered, indexable, mutable
monthly_sales = [12000, 15500, 13800]

# tuple — fixed record, cannot be changed after creation
reporting_period = ("Q1", 2026)

# set — unique values only, great for dedup
unique_customers = {"Acme", "Globex", "Acme"}
print(unique_customers)

# dict — key → value lookup
customer = {
    "name": "Acme Corp",
    "region": "West",
    "ltv": 125000
}
print(customer["region"])
{'Acme', 'Globex'} West
05 Why the choice of structure changes the algorithm click to expand +

This is the heart of Wirth's formula: the same task — "find this customer's record" — needs a completely different algorithm depending on how the data is stored.

CUSTOMERS STORED AS A LIST

Python has to scan every record, one at a time, until it finds a match.

for c in customer_list:
    if c["id"] == "C1042":
        return c
Scans up to 10,000 records — O(n)
CUSTOMERS STORED AS A DICT (keyed by ID)

Python jumps straight to the record using a hash lookup.

customer_dict["C1042"]
One direct lookup — O(1)

For 100 customers, this barely matters. For 500,000 transaction rows, it's the difference between a script that runs in a second and one that times out. The data structure you choose is part of the algorithm's performance — that's exactly why Wirth wrote the formula as an equation, not two separate topics.

Reusability

Functions

A function packages a piece of logic so you can reuse it, test it once, and name it clearly. This is how small pieces of control flow become a real, maintainable analytics script.

06 Defining and calling functions click to expand +
discount.pypython 3
def calculate_discount(price, tier, rate=0.10):
    """Return the discounted price for a given customer tier."""
    if tier == "Platinum":
        rate = 0.20
    elif tier == "Gold":
        rate = 0.15
    return round(price * (1 - rate), 2)

print(calculate_discount(100, "Gold"))
print(calculate_discount(100, "Standard"))
85.0 90.0

The four parts, named

  • Parameters — price, tier, rate: the inputs the function needs. rate=0.10 is a default, used only if the caller doesn't supply one.
  • Docstring — the quoted line right after def; documents what the function does for the next person (often future-you).
  • Body — the indented logic, which can use any control flow you've already learned.
  • Return value — return sends a result back to wherever the function was called, so you can store it, print it, or feed it into another function.
07 A few things worth knowing early click to expand +

f-strings for readable output

f"Revenue: ${revenue:,.2f}" — the f prefix lets you drop variables directly into a string, and :,.2f formats a number with commas and two decimals. You'll use this constantly in reports.

Comments

Anything after # is ignored by Python — use it to explain why, not just what, especially around business logic that isn't obvious from the code alone.

List comprehensions (a Python signature move)

comprehension.pypython 3
prices = [9.99, 24.99, 150.00, 5.50]
high_value = [p for p in prices if p > 20]
print(high_value)
[24.99, 150.0]

Read it as: "give me p, for each p in prices, but only if p > 20." It's a loop and a filter condensed into one line — you'll see this constantly in real analytics code.

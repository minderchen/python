Functions — Basic to Advanced

// package logic once, call it everywhere

A function is a named, reusable block of logic. This sheet builds from defining and calling a function up through scope, flexible arguments, and the two ideas that make functions worth the syntax in the first place: modularity and reuse.

def calculate_discount(price, tier):

The four parts, named

  • Parameters — price, tier: placeholders for whatever values get passed in when the function is called.
  • Docstring — the quoted line documenting what the function does, for the next person reading it.
  • Body — the indented logic, using any control flow you already know.
  • Return value — sends a result back to the caller, so it can be stored, printed, or fed into something else.

03 return vs. print — a common early mix-up click to expand +

print() shows something on screen. return sends a value back so your program can actually use it. A function with no return hands back None.

return_vs_print.pypython 3
def add_printer(a, b):
    print(a + b)     # just displays it — gives nothing back

def add_returner(a, b):
    return a + b   # hands the value back to the caller

result_a = add_printer(2, 3)
result_b = add_returner(2, 3)

print(f"result_a = {result_a}")
print(f"result_b = {result_b}")
print(result_b * 10)  # this works
# result_a * 10 would fail — you can't do math on None
5 result_a = None result_b = 5 50
04 Scope — local vs. global variables click to expand +

A variable created inside a function only exists inside that function. It doesn't leak out, and it doesn't see itself overwriting anything outside.

scope.pypython 3
tax_rate = 0.08   # global — visible everywhere

def apply_local_discount(price):
    tax_rate = 0.0   # local — only exists inside this function
    return price * (1 + tax_rate)

print(apply_local_discount(100))  # uses the local tax_rate = 0.0
print(tax_rate)                      # the global one is untouched
100.0 0.08

This is a feature, not a bug: it means a function's internal variables can't accidentally corrupt the rest of your program. Each call also gets its own fresh set of local variables.

kwargs_demo.pypython 3

    return kwargs

print(build_report(region="West", quarter="Q1", total=45000))

Whatever keyword arguments the caller passes get collected into a single dictionary named kwargs — useful for functions that accept optional, open-ended settings.

The payoff

Modularity & Reuse

This is why functions exist. Without them, the same logic gets copy-pasted everywhere it's needed — and every copy is a place a bug can hide. Watch what happens when the discount rate needs to change.

What this buys you

  • Reuse — write the logic once, call it from anywhere in your program (or in a different project entirely).
  • Maintainability — fix a bug or update a rule in one place, and every call site is correct immediately.
  • Readability — calculate_discount(100) tells the reader what's happening; ten lines of inline math doesn't.
  • Testability — you can test one function in isolation instead of re-checking the same logic every place it's copied.
07 Composition — functions calling functions click to expand +

Small functions become building blocks for bigger logic. Step through this pipeline one stage at a time.

pipeline.pypython 3
def clean_price(raw):
    return float(raw.replace("$", "").replace(",", ""))

def apply_discount(price, rate=0.10):
    return round(price * (1 - rate), 2)

def format_currency(value):
    return f"${value:,.2f}"

def process(raw_price):
    price = clean_price(raw_price)
    discounted = apply_discount(price)
    return format_currency(discounted)

Each function does one clear job. process() doesn't need to know how cleaning or formatting works — it just trusts each piece to do its part.

08 Lambda — small, throwaway functions click to expand +

A lambda is a one-line, unnamed function — handy when you need a quick function to pass into something else, like a sort key.

lambda_demo.pypython 3
products = [("Mouse", 24.99), ("Monitor", 210.00), ("Cable", 8.50)]

# sort by price (the second item in each tuple)
products.sort(key=lambda item: item[1])
print(products)
[('Cable', 8.5), ('Mouse', 24.99), ('Monitor', 210.0)]

lambda item: item[1] is equivalent to writing a full def function that returns item[1] — it just isn't worth naming for a one-off use like this.

09 Practical pattern — tier-based discounts click to expand +

Use a dictionary when a function needs to select from named business rules. This keeps the rates separate from the calculation and makes adding a new tier a one-line change.

discounts.pypython 3
DISCOUNT_RATES = {
      "Platinum": 0.20,
      "Gold": 0.15,
      "Standard": 0.10
  }


  def calculate_discount(price, tier):
      """Return the discounted price for a given customer tier."""
      rate = DISCOUNT_RATES.get(tier, DISCOUNT_RATES["Standard"])
      return round(price * (1 - rate), 2)
calculate_discount(100, "Platinum") 80.0 calculate_discount(100, "New tier") 90.0

Why this is structured this way

  • DISCOUNT_RATES is uppercase because it is a module-level constant: the rules have one named source rather than being duplicated inside the function.
  • .get(tier, DISCOUNT_RATES["Standard"]) looks up a recognized tier and safely falls back to the Standard rate when the tier is missing or unexpected.
  • The function returns a value instead of printing it, so callers can display it, store it, or test it independently.
  • round(..., 2) produces a price rounded to two decimal places, which is appropriate for a simple money-display example.
